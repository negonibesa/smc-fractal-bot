## 🔴 Открыто — приоритет

1. **Бэктест не симулирует ре-оптимизацию по ходу времени.** Ни `run_backtest()`, ни `run_walk_forward()` не меняют параметры на лету — оба тестируют **один фиксированный конфиг**. Живой бот (`main.py`) реально переоптимизируется каждые ~30 дней или по триггеру просадки. Нужен отдельный rolling-раннер поверх `backtest.py`+`auto_optimizer.py`, который на каждом окне видит только прошлые данные и реально меняет параметры между окнами, перенося баланс. Не начинали делать.

2. **`walk_forward.py` — прочитал код. Это НЕ настоящий walk-forward с переоптимизацией**, только вывод.** Вопрос без ответа: в anchored-сплитах параметры реально переоптимизировались на растущем train-окне, или это один и тот же конфиг просто прогнали по разным окнам? Разница принципиальная для интерпретации результатов. Нужно скинуть сам файл.

3. **SOL исключён из `walk_forward.py` намеренно** (`enabled: false` в settings.yaml) — по совету "убрать слабую пару из живого конфига", но применили это и к самой проверке, из-за чего никогда не узнаем, подтвердила бы честная OOS-проверка его слабость. Стоит вернуть SOL в сам прогон (можно держать выключенным в живой торговле отдельно).
   **Статус**: хардкод `!= 'SOLUSDT'` заменён на `a.get('enabled', True)`. Теперь walk_forward.py использует `enabled` из settings.yaml. Для теста SOL — поставить `enabled: true`, для live — обратно `false`.

4. **Windows-кодировка роняет `walk_forward.py`** до печати финальной сводки:
   ```python
   import sys, io
   sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
   ```
   либо убрать юникод-символы (`─`, `✓`, `✗`) из принтов.
   **Статус**: `─` в separator-строке заменён на `-` (唯一的问题行). Остальные `→` и `─` в комментариях/logger'ах не печатаются в stdout — не падают.

## 🟡 Открыто — не критично, не забыть

- `position_tracker.py` — свой `update_trailing()` дублирует `TrailingManager` из `main.py`, нигде не вызывается (мёртвый код), но расходится по логике (нет защиты от мелких обновлений)
- `order_executor.close_position()` не проверяет, что закрытие реально исполнилось (в отличие от входа, где есть 5 попыток проверки)
- Три потока (Telegram-команды, Flask-дашборд, главный цикл) читают общее состояние без `threading.Lock`
- Токен Telegram-бота теоретически может утечь в лог через текст исключения `requests` при сетевой ошибке
- `interval="240"` и `candle_interval = 4*3600` — таймфрейм захардкожен в двух не связанных местах
- `send_error()` используется и для позитивного события (успешная авто-оптимизация) — вводит в заблуждение по тону
- Пропуск дневного/недельного Telegram-отчёта без докатки, если бот не работал в окне 00:00–00:10 UTC
- Партиал-филлы / ограничения ликвидности на менее ликвидных парах (DOGE, RENDER) не смоделированы в бэктесте
