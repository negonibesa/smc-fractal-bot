# Исправление учёта издержек (найдено 2026-09-26)

## Суть

В `h21_portfolio.py` комиссия taker списывалась **дважды на каждой стороне**:

```python
entry = p['o'][j] * (1 + SLIP) * (1 + TAKER)   # комиссия внутри цены
cash -= qty * entry * TAKER                      # :115 комиссия второй раз

px = q['stop'] * (1 - SLIP) * (1 - TAKER)        # :127 комиссия внутри цены
cash -= qty * px * TAKER                         # :129 комиссия второй раз
```

Проскальзывание при этом применялось один раз — верно.

Trade-level PF (строка 131) считался по ценам и потому был **верен**:
комиссия в нём учтена один раз. Расходились именно доходность и
просадка, потому что они строились по `cash`.

Вторая, меньшая ошибка: размер позиции считался от `cash`, а не от
полной эквити с нереализованным PnL (`h21_portfolio.py:105`).

## Масштаб

Пул 14, лимит 6 позиций, риск 0.50%, 30 месяцев:

| учёт | итог | просадка | PF | expectancy |
|---|---|---|---|---|
| комиссия ×2, размер от cash (H21) | 170.6% | 20.7% | 1.33 | +0.1188R |
| комиссия ×1, размер от эквити (верно) | 184.0% | 20.4% | 1.34 | +0.1209R |

Ошибка занижала итог на **13.4 п.п.** и завышала просадку на **0.3 п.п.**
Ошибка в базе размера — ещё **7.3 п.п.**

## Правильная конвенция

```
вход/выход = цена бара x (1 ± SLIP)     только проскальзывание
комиссия    = qty x цена x TAKER        отдельно, в деньгах, один раз
PnL         = qty*(выход − вход)*side − комиссия_выход
R           = PnL / (qty x risk_per_unit)
```

Эквити и R по построению согласованы — комиссию нельзя потерять или
удвоить. Реализация: `h24_unified_cost.py`.

## Сверка

При риске 0.50% комиссия составляет ≈ 3.6% от риска на сделку
(notional ≈ 26× риска при ATR/price ≈ 1.93%). Ожидаемое смещение
expectancy ≈ 0.036R — наблюдаемое 0.1209 − 0.1305 = 0.0096R в H22
учитывает, что H22 применял комиссию частично. Сходится в порядке
величины.

## Отдельно: Calmar не выбирает уровень риска

`Calmar p50` растёт монотонно: 8.85 → 10.23 → 12.66 → 18.32 для риска
0.25 / 0.35 / 0.50 / 0.75%. При постоянном положительном edge
фиксированное дробление всегда даёт растущий Calmar, и метрика
де-факто советует максимальное плечо. Для выбора уровня риска
использовать только допустимую просадку:

- 0.25% → P(DD>30%) = 0.0%
- 0.35% → P(DD>30%) = 0.2%
- 0.50% → P(DD>30%) = 3.3%
- 0.75% → P(DD>30%) = 28.6%
